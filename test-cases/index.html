AGIMA / Форма «Стать клиентом» / Поле Email принимает корректный email

Позитивный сценарий. Priority: High. Проверка корректного email при валидном заполнении формы.

Type

Positive

Priority

High

Preconditions

  • Открыта страница https://www.agima.ru/clients/
  • Пользователь находится в блоке Контактные данные

Steps

  1. Ввести в поле Email корректное значение, например test@example.com
  2. Заполнить остальные обязательные поля валидными данными
  3. Проверить состояние поля Email
  4. Нажать кнопку отправки формы

Expected Result

Поле Email не подсвечивается ошибкой, значение считается валидным, а форма может быть отправлена при корректном заполнении остальных обязательных полей.

AGIMA / Форма «Стать клиентом» / Поле Email отклоняет невалидные значения

Негативный сценарий. Priority: High. Проверка, что форма не принимает некорректные email-значения.

Type

Negative

Priority

High

Preconditions

  • Открыта страница https://www.agima.ru/clients/
  • Пользователь находится в блоке Контактные данные

Test Data

  • test@
  • test @2
  • test@и

Steps

  1. Ввести в поле Email одно из невалидных значений: test@, test @2, test@и
  2. Проверить состояние поля
  3. Попробовать отправить форму

Expected Result

Поле должно показывать ошибку валидации, невалидное значение не должно считаться корректным email, а форма не должна отправляться, пока email не исправлен.

AGIMA / Форма «Стать клиентом» / Поле «Телефон» отклоняет невалидные значения

Негативный сценарий. Priority: High. Проверка, что поле телефона отклоняет заведомо невалидные значения.

Type

Negative

Priority

High

Preconditions

  • Открыта страница https://www.agima.ru/clients/
  • Пользователь находится в блоке Контактные данные

Test Data

  • 1
  • а
  • abc
  • 123abc
  • длинный произвольный текст

Steps

  1. Ввести в поле Телефон по очереди невалидные значения: 1, а, abc, 123abc, длинный произвольный текст
  2. После каждого значения проверять состояние поля
  3. Попробовать отправить форму

Expected Result

Поле должно отклонять заведомо невалидные значения, одиночные символы, буквы, смешанные строки и произвольный текст не должны считаться валидным номером, а форма не должна отправляться с некорректным телефоном.

AGIMA-TC-005•Учебный проект: обучение QA Manual•AGIMA / Homepage / Mobile UI
AGIMA / Главная страница / Мобильная версия корректно отображает контент без предварительного scroll

Негативный сценарий. Priority: High. Проверка initial render мобильной главной без предварительного scroll.

Type

Negative

Priority

High

Preconditions

  • Открыта главная страница https://www.agima.ru/
  • Используется mobile viewport или реальное мобильное устройство

Steps

  1. Открыть главную страницу в мобильной версии
  2. Дождаться полной загрузки
  3. Не выполнять scroll
  4. Проверить отображение первого и следующих контентных блоков

Expected Result

Страница должна корректно инициализировать контент сразу после загрузки, блоки не должны доотрисовываться только после первого scroll, а пользователь должен видеть корректную мобильную верстку без дополнительного действия.

AGIMA-TC-006•Учебный проект: обучение QA Manual•AGIMA / Homepage / Mobile UI
AGIMA / Главная страница / В мобильной версии число в анимированном счётчике не накладывается на подпись

Негативный сценарий. Priority: Medium. Проверка анимированного счётчика в мобильной версии.

Type

Negative

Priority

Medium

Preconditions

  • Открыта главная страница https://www.agima.ru/
  • Используется mobile viewport или реальное мобильное устройство
  • Пользователь дошёл до блока со счётчиком количества специалистов

Steps

  1. Открыть главную страницу в мобильной версии
  2. Прокрутить до секции со счётчиком
  3. Наблюдать за анимацией цифрового значения во время запуска

Expected Result

Число должно отображаться в пределах своей зоны, анимация не должна заходить на текстовую подпись, а текст и цифры должны оставаться читаемыми во время всей анимации.
